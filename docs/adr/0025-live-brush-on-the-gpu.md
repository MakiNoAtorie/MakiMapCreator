# Live brush on the GPU

This refines ADR-0014 (brush stroke visible in one frame). While stroke parts are on their way through the edit worker, the canvas shows them from a GPU copy of the drawn heights, so the stroke is shaded under the pen in the frame its stamps are made, as in mapgen4 and Wonderdraft. The CPU stroke session stays the source of truth for undo, saving and derived layers; the copy is display only.

- The copy is the height raster of the last complete canvas render (the visible area at the drawn pyramid level, 2 pixels of margin), in an R32Float texture. Each render carries a mark: how many stamps of the current stroke were in the project when it read its tiles, and the stroke's flatten level (the edit worker writes it under the project lock). The copy is that raster plus every sent part the mark does not cover.
- Stamps run in compute passes (`render/src/live.wgsl`): one dispatch per part over the parts' box, each texel applying the part's stamps in order; smooth takes two dispatches per stamp (row means, then box means), because each stamp reads the heights the one before left. All modes of the CPU brush run there. Corners hash with a u32 port of splitmix64; core gives each octave's hash prefix and, per node column and row, its part of the lattice point as a whole corner and a fraction in 2^-32 units (`detail_tables`), because WGSL has no u64 or f64; the shader adds the parts as integers, so the fraction loses nothing before it becomes f32. Floats are f32; tanh and exp are not used, because WARP's are off by about 1e-4.
- Flatten's level is the CPU's from the mark, or, for the part that starts the stroke, read from the copy under its first stamp.
- Shading is the height pass of the shown map's kind, built for the window format and drawn by an egui paint callback over the canvas image. Outside the copy the canvas image shows.
- The copy is uploaded at a stroke's first part and again when a complete render covers other pixels (pan, zoom). A complete render that covers the same pixels only retires the parts it shows. When no part is left the canvas image, which then has every stamp, shows alone.

We rejected a GPU copy that is the source of truth (read back for undo and save): it would make the result depend on the GPU and break seam-safe determinism (ADR-0008, ADR-0021).

## Reference maths

`mmc_core::brush` is the reference; a port changes with it and `render/tests/live.rs` holds them together.

- Pixels are global pixel indices `g = round(at / mpp - 0.5)` with centres `(g + 0.5) * mpp`, root-space metres.
- `stamp_weight = brush_weight(d², falloff) * (1 + soft(amount * n))`, `soft(x) = x / sqrt(1 + x²)`, `d² = |at - centre|² / radius²`, 0 outside the disc; `amount` is clamped to 0..1, so the factor stays in 0..2 and detail never turns a stamp around, and no clamp makes a flat top. `brush_weight` is 1 inside the core `d² ≤ (1 - falloff)²` and `t²(3 - 2t)`, `t = (1 - d²) / (1 - core)`, outside: no crease at the core edge, which a texel's plane would miss (see Consequences).
- `n` is `detail_noise(...).at(v, raise)`, `v` the pixel before the stamp: the value noise, or for a raise (an add with no target and strength > 0) `value * (1 - s) + 2 * ridged * s`, `s = smoothstep(150 m, 1200 m, v)` (`RIDGE_HEIGHTS`, `RIDGE_GAIN`), so high ground takes ridges; either times `smoothstep(0, 20 m, |v - WATER_LEVEL|)` (`COAST_BAND`), so detail never speckles the coast.
- `detail_noise`: nodes every 4 global pixels at `g = 4k`, each with two sums over the octaves `o` = 0..6 whose cell `scale / 2.01^o` (`LACUNARITY`) is at least 7 pixels. Octave `o` maps root point `p` to lattice point `q = (scale / 2.01^o)^-1 * R^o * p + (0.37, 0.71) * (o + 1)`, `R` the rotation with cos 0.8, sin 0.6, so the octaves' lattices never line up. `n_o` is gradient noise at `q`: corners `floor(q) + (0|1, 0|1)` hashed by `rng::lattice` (splitmix64 of the octave prefix xor the corner, each coordinate wrapped to 32 bits), the top 3 bits picking one of 8 unit gradients (axes and diagonals), dot products with the offsets mixed by the quintic `6t^5 - 15t^4 + 10t^3`. Value is `sum(0.5^o * n_o) / 0.45` (`VALUE_SPREAD`). Ridged is Musgrave's ridged multifractal: `signal_o = (1 - |sqrt(2) * n_o|)² * weight_o`, `weight_0 = 1`, `weight_o+1 = signal_o * (2 - signal_o)` (his `min(1, 2 * signal)` without the crease), `(sum(0.5^o * signal_o) - 1) / 0.6` (`RIDGED_MID`, `RIDGED_SPREAD`). Neither is clamped; both have mean about 0 and spread about 0.45. A pixel is the uniform quadratic B-spline of nodes `k - 1..=k + 1`, `k = floor((g + 2) / 4)`, `t = ((g + 2) mod 4) / 4`, `0.5 * ((1 - t)² a + (1 + 2t(1 - t)) b + t² c)`, first in y, then in x; unlike a bilinear mix it has no slope steps at nodes, which hillshade showed as a grid. The app gives roughen a scale equal to the brush size.
- The ridged weight `s(2 - s)` is a smooth stand-in for Musgrave's `clamp(signal * gain, 0, 1)` with gain 2: the same slope at 0, and no crease where the clamp starts.
- Modes, with `w` the weight and `p` the pressure: add `v += strength * p * w`; raise-to and lower-to `v += (target - v) * min(1, p * w)`, never the other way; smooth `v += (mean - v) * min(1, strength * p * w)`, `mean` the box mean of the `(2k + 1)²` pixels around inside the map, `k = max(1, ceil(radius px / 4))`, read before the stamp; flatten `v += (level - v) * min(1, strength * p * w)`, `level` the pixel under the stroke's first stamp before the stroke; roughen `v += a * soft(d / a)`, `d = strength * p * falloff * n`, `a = |v - WATER_LEVEL|`, so it never moves a pixel across the water level (a rounding that would keeps `v`).
- A port with f32 or another hash agrees within its rounding, not bit for bit.

## Consequences

- At level 0 GPU and CPU agree within 1e-3 m per stroke (measured up to 8.5e-4 m, 7 f32 steps, at 1150 m under WARP over 200 seeds), the shaded colours within 1 per channel, so the hand-over shows no jump. The copy is uploaded at each stroke's first part, so errors do not add up over strokes. Smooth's box stops at the copy's edge, where the CPU's goes on to the map's.
- At pyramid levels above 0 a texel is the mean of its level-0 pixels, as the CPU pyramid: a stamp changes it by the mean change of its pixels (all of them up to level 2, 4x4 of them above), each starting on the plane of the texel's slope. Lowering adds without detail are linear, so they match within 1e-3 m. With detail the weight depends on the height (ridges, the coast fade, roughen's bound), so the others match within 0.2 m, colours within 1 per channel, where the texel never was in the coast band (measured up to 0.11 m at level 2 on an 800 m hill, over 40 seeds); where it was, and the slope changes within a texel, up to about 0.6 m, which can move the coastline and its shading by a texel. A crease in painted ground (the old `t²` falloff had one at the core edge) breaks the plane start: it made the level-2 hand-over fail on about 1 seed in 16.
- A stroke past the copy's edge is drawn there by the canvas image when the CPU has applied it; the commit is the CPU's either way.
- A failed part, or a flatten part that starts off the copy, hides the copy until the next complete render.
